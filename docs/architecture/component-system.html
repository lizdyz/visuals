1. The Component Truth: What Actually Gets Leveled Up

CRITICAL CONCEPT: The entire platform exists to level up Components. Everything else (Missions, Journeys, Quests, Sparks) is just the DELIVERY SYSTEM for Component advancement.

What This Means in Code:

  • Journey = Parent container (the filing cabinet)
  • Component = Individual scoreable entity (each drawer)
  • Maturity Level (L1-L5) = The current state of that drawer
  • Quest = The project that fills a drawer (levels it up)
  • Spark = Individual file you put in the drawer (task)

2. Component State Machine: The Leveling Logic

KEY INSIGHT: A Component has TWO progress metrics that work together: LEVEL (discrete) and PROGRESS (continuous).

The Two-Metric System

Metric Type Values Meaning Database Field
Current Maturity Level Discrete State L1, L2, L3, L4, L5 Where you ARE current_maturity_level
Progress to Next Level Continuous Progress 0-100% How far toward NEXT level progress_to_next_level

State Transition Flow

stateDiagram-v2 [*] --> L1: Initial Assessment L1 --> L2: Complete Quest 1
Progress reaches 100% L2 --> L3: Complete Quest 2
Progress reaches 100% L3 --> L4: Complete Quest 3
Progress reaches 100% L4 --> L5: Complete Quest 4
Progress reaches 100% L5 --> [*]: Mastery Achieved note right of L1 L1 (Lacking) Progress: 0-100% → toward L2 end note note right of L2 L2 (Learning) Progress: 0-100% → toward L3 end note note right of L3 L3 (Launching) Progress: 0-100% → toward L4 end note note right of L4 L4 (Leveraging) Progress: 0-100% → toward L5 end note note right of L5 L5 (Leading) Progress: N/A (No next level) end note

State Transition Rules:

  1. Initial State: All Components start at L1 with 0% progress (set during MIRROR assessment)
  2. Progress Accumulation: As user completes Sparks within a Quest, progress increases
  3. Quest Completion Trigger: When Quest is completed, ALL Components it advances get checked
  4. Level Advancement: If progress >= 100%, Component advances one level
  5. Progress Reset: Upon leveling up, progress resets to 0% toward NEXT level
  6. L5 Special Case: At L5, progress_to_next_level becomes NULL (no next level exists)

3. Database Logic: What Fires When

Component Table Schema (Expanded)

CREATE TABLE components ( component_id UUID PRIMARY KEY, component_name VARCHAR(255) NOT NULL, parent_journey_id UUID NOT NULL REFERENCES journeys(journey_id), description TEXT, -- THE TWO CRITICAL FIELDS -- current_maturity_level ENUM('L1', 'L2', 'L3', 'L4', 'L5') NOT NULL DEFAULT 'L1', progress_to_next_level INTEGER CHECK (progress_to_next_level >= 0 AND progress_to_next_level <= 100) DEFAULT 0, -- TAGGING -- domain_tags INTEGER[] DEFAULT '{}', tenet_tags INTEGER[] DEFAULT '{}', -- TRACKING -- last_updated_at TIMESTAMP DEFAULT NOW(), created_at TIMESTAMP DEFAULT NOW(), -- METADATA -- time_at_current_level_days INTEGER DEFAULT 0, total_quests_completed INTEGER DEFAULT 0, deliverable_ids UUID[] DEFAULT '{}' );

Quest Completion Trigger Logic

-- TRIGGER: When Quest Status Changes to 'completed' CREATE OR REPLACE FUNCTION handle_quest_completion() RETURNS TRIGGER AS $$ DECLARE component_record RECORD; advancement_weight INTEGER; BEGIN -- Quest just completed, process all Components it advances FOR component_record IN SELECT c.component_id, c.current_maturity_level, c.progress_to_next_level, cqm.advancement_type FROM components c JOIN component_quest_map cqm ON c.component_id = cqm.component_id WHERE cqm.quest_id = NEW.quest_id LOOP -- Determine progress increment based on Quest's target transition advancement_weight := CASE WHEN NEW.target_level_transition = 'L1→L2' THEN 100 -- Full advancement WHEN NEW.target_level_transition = 'L2→L3' THEN 100 WHEN NEW.target_level_transition = 'L3→L4' THEN 100 WHEN NEW.target_level_transition = 'L4→L5' THEN 100 ELSE 50 -- Partial if supporting END; -- Add progress UPDATE components SET progress_to_next_level = LEAST(progress_to_next_level + advancement_weight, 100), last_updated_at = NOW() WHERE component_id = component_record.component_id; -- Check if ready to level up IF (component_record.progress_to_next_level + advancement_weight) >= 100 THEN -- Level up the Component UPDATE components SET current_maturity_level = CASE WHEN current_maturity_level = 'L1' THEN 'L2' WHEN current_maturity_level = 'L2' THEN 'L3' WHEN current_maturity_level = 'L3' THEN 'L4' WHEN current_maturity_level = 'L4' THEN 'L5' ELSE current_maturity_level -- Stay at L5 END, progress_to_next_level = CASE WHEN current_maturity_level = 'L4' THEN NULL -- Reached L5, no next level ELSE 0 -- Reset for next level END, time_at_current_level_days = 0, total_quests_completed = total_quests_completed + 1, last_updated_at = NOW() WHERE component_id = component_record.component_id AND progress_to_next_level >= 100; -- Log the level advancement event INSERT INTO component_level_events (component_id, old_level, new_level, quest_id, timestamp) VALUES ( component_record.component_id, component_record.current_maturity_level, CASE WHEN component_record.current_maturity_level = 'L1' THEN 'L2' WHEN component_record.current_maturity_level = 'L2' THEN 'L3' WHEN component_record.current_maturity_level = 'L3' THEN 'L4' WHEN component_record.current_maturity_level = 'L4' THEN 'L5' END, NEW.quest_id, NOW() ); END IF; END LOOP; -- Update Journey aggregate maturity PERFORM update_journey_maturity( (SELECT parent_journey_id FROM quests WHERE quest_id = NEW.quest_id) ); RETURN NEW; END; $$ LANGUAGE plpgsql; CREATE TRIGGER quest_completion_trigger AFTER UPDATE OF status ON quests FOR EACH ROW WHEN (NEW.status = 'completed' AND OLD.status != 'completed') EXECUTE FUNCTION handle_quest_completion();

Journey Maturity Aggregation

-- FUNCTION: Calculate Journey's overall maturity from its Components CREATE OR REPLACE FUNCTION update_journey_maturity(journey_id_param UUID) RETURNS VOID AS $$ DECLARE avg_level DECIMAL; level_mapping JSONB := '{"L1": 1, "L2": 2, "L3": 3, "L4": 4, "L5": 5}'::JSONB; BEGIN -- Calculate average Component level for this Journey SELECT AVG( CAST(level_mapping->>current_maturity_level AS INTEGER) ) INTO avg_level FROM components WHERE parent_journey_id = journey_id_param; -- Map average back to discrete level UPDATE journeys SET current_maturity_level = CASE WHEN avg_level < 1.5 THEN 'L1' WHEN avg_level < 2.5 THEN 'L2' WHEN avg_level < 3.5 THEN 'L3' WHEN avg_level < 4.5 THEN 'L4' ELSE 'L5' END, last_activity_at = NOW() WHERE journey_id = journey_id_param; END; $$ LANGUAGE plpgsql;

5. Quest-Component Connection: How They Link

KEY RELATIONSHIP: One Quest advances 1-3 Components. One Component is advanced by 1-4 Quests (the standard Quest sequence).

The Mapping Table

CREATE TABLE component_quest_map ( map_id UUID PRIMARY KEY DEFAULT gen_random_uuid(), component_id UUID NOT NULL REFERENCES components(component_id), quest_id UUID NOT NULL REFERENCES quests(quest_id), -- HOW this Quest affects this Component advancement_type VARCHAR(50) NOT NULL CHECK (advancement_type IN ('primary', 'secondary', 'supporting')), -- WHAT level transition this represents from_level ENUM('L1', 'L2', 'L3', 'L4') NOT NULL, to_level ENUM('L2', 'L3', 'L4', 'L5') NOT NULL, -- WEIGHT of this Quest's impact (usually 100 for primary, 50 for secondary) progress_weight INTEGER NOT NULL DEFAULT 100, created_at TIMESTAMP DEFAULT NOW(), UNIQUE(component_id, quest_id) );

6. The Complete Flow: Spark → Component Level Change

sequenceDiagram participant User participant UI participant API participant DB participant NotificationService User->>UI: Completes final Spark in Quest UI->>API: POST /sparks/{spark_id}/complete API->>DB: UPDATE sparks SET status='completed' DB->>DB: Check: All Sparks in Quest completed? alt All Sparks Complete DB->>DB: UPDATE quests SET status='completed' DB->>DB: TRIGGER: handle_quest_completion() loop For Each Mapped Component DB->>DB: Add progress_weight to component alt Progress >= 100% DB->>DB: Advance maturity_level by 1 DB->>DB: Reset progress_to_next_level = 0 DB->>DB: INSERT component_level_events DB->>NotificationService: Component leveled up! end end DB->>DB: Update Journey aggregate maturity DB->>API: Quest completion + Component updates API->>UI: Completion data + level changes UI->>User: 🎉 Show celebration + new levels else Sparks Remaining DB->>API: Spark completed, Quest still in progress API->>UI: Progress update UI->>User: Show next Spark end

Step-by-Step Execution:

  1. User Action: Completes Spark (fills out form, answers question, creates content)
  2. Spark Update: Spark record marked as completed
  3. Quest Check: System checks if ALL Sparks in parent Quest are now complete
  4. Quest Completion: If yes, Quest status → completed, triggers database function
  5. Component Loop: For each Component mapped to this Quest:
    • Add progress based on advancement_type (100%, 50%, 25%)
    • If progress >= 100%, level up and reset progress
    • Log the level change event
  6. Journey Update: Recalculate Journey's aggregate maturity from all its Components
  7. UI Feedback: Show celebration, updated badges, new unlocked Quests
  8. Story Trail: Log achievement to user's Story Trail for reflection

7. Recommendation Engine: What Quest Next?

KEY QUESTION: How does the system decide which Quest to recommend to the user next?

Recommendation Algorithm

-- FUNCTION: Get next best Quest recommendation for user CREATE OR REPLACE FUNCTION get_recommended_quest(user_id_param UUID) RETURNS TABLE ( quest_id UUID, quest_name VARCHAR(255), reason TEXT, score INTEGER ) AS $$ BEGIN RETURN QUERY WITH user_context AS ( -- Get user's current state SELECT mission_id, array_agg(DISTINCT journey_id) as active_journeys, array_agg(DISTINCT component_id) as components_below_l3 FROM user_missions um JOIN mission_journey_map mjm USING (mission_id) JOIN components c ON c.parent_journey_id = mjm.journey_id WHERE um.user_id = user_id_param AND um.status = 'active' AND c.current_maturity_level IN ('L1', 'L2') GROUP BY mission_id ), quest_scores AS ( -- Score all available Quests SELECT q.quest_id, q.quest_name, -- Scoring logic (CASE WHEN q.parent_journey_id = ANY(uc.active_journeys) THEN 50 ELSE 0 END) + (CASE WHEN EXISTS ( SELECT 1 FROM component_quest_map cqm WHERE cqm.quest_id = q.quest_id AND cqm.component_id = ANY(uc.components_below_l3) ) THEN 30 ELSE 0 END) + (CASE WHEN q.status = 'not_started' THEN 20 ELSE -50 END) AS score, -- Reason text CASE WHEN q.parent_journey_id = ANY(uc.active_journeys) THEN 'Advances your active Journey' WHEN EXISTS ( SELECT 1 FROM component_quest_map cqm WHERE cqm.quest_id = q.quest_id AND cqm.component_id = ANY(uc.components_below_l3) ) THEN 'Levels up Components needing attention' ELSE 'Available Quest' END AS reason FROM quests q CROSS JOIN user_context uc WHERE q.status != 'completed' ) SELECT qs.quest_id, qs.quest_name, qs.reason, qs.score FROM quest_scores qs ORDER BY qs.score DESC LIMIT 5; END; $$ LANGUAGE plpgsql;

Scoring Factors

Factor Points Reasoning
Quest is in active Journey +50 User chose this Journey in their Mission
Advances Component(s) below L3 +30 Fills identified gaps from MIRROR assessment
Quest not yet started +20 Fresh experience, avoid repetition
Quest already completed -50 Strongly discourage repeats (can still access)
Sequential prerequisite met +15 Natural Quest 1→2→3→4 progression
Multiple Components advanced +10 Efficient use of time

10. Critical Questions Answered

Q: How do you know WHICH Components to level up?

A: The MIRROR assessment sets initial levels. The recommendation engine suggests Quests that advance Components below L3 first, prioritizing those in the user's active Mission.

Q: Can one Quest advance multiple Components at once?

A: Yes! That's the power of the system. The LinkedIn Workshop Quest advances "Brand Identity" (primary), "Marketing Channels" (secondary), and "Content Creation" (supporting) simultaneously.

Q: What happens if a user skips Quests and jumps ahead?

A: The system tracks progress per Component, not per Quest sequence. If they skip Quest 2, their Component stays at its current level. Quest 3 won't advance them from L1 to L4 - each Quest moves them ONE level based on its target_level_transition.

Q: How does Journey maturity get calculated if Components are at different levels?

A: Journey maturity is the AVERAGE of its Component levels (converted to numbers: L1=1, L2=2, etc.), then rounded back to the nearest level. So if 4 Components are L2 and 2 are L3, the Journey shows as L2.

Q: Where does the 22 Domains and 22 Tenets fit in?

A: They are TAGS. Every Component, Quest, and Spark can be tagged with relevant Domains (operational perspective) and Tenets (skill development perspective). This enables filtering, gap analysis, and cross-journey pattern detection.

Q: What's the difference between Component progress and Quest progress?

A: Quest progress = % of Sparks completed in that Quest. Component progress = % toward next maturity level (accumulated from multiple Quests). Quest completion is binary (done/not done). Component progress is cumulative.

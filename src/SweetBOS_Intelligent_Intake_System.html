Intelligent Intake & Validation System

Extract → Validate → Guide | Generated: November 9, 2025

Core Philosophy: Advisors already HAVE most of their answers - buried in documents, to-do lists, emails, notes, and existing systems. Don't make them manually input everything. EXTRACT intelligence from what they already have, then guide them to validate and fill gaps.

The UX Revolution: Every interaction should minimize clicks, scrolls, and manual entry. If we can parse it, we parse it. If we can infer it, we infer it. If we can auto-complete it, we auto-complete it. Users only validate, correct, and fill gaps.

1. The Core UX Principle: Minimum Viable Friction

Every Click Costs Momentum

Traditional form design:

  • Click on field
  • Type answer
  • Scroll to next field
  • Click on field
  • Type answer
  • Scroll to submit
  • Click submit
  • Result: 7+ interactions for 2 answers

SweetBOS Philosophy:

  • User drops in existing document
  • AI extracts answers
  • User sees pre-filled fields
  • User validates with single click per answer
  • Only stops to manually answer what's missing
  • Result: 2 interactions for 2 answers (if data exists)

Scenario: Building FAQ list

  1. Click "Add FAQ"
  2. Type question #1
  3. Click "Add Answer"
  4. Type answer #1
  5. Click "Save"
  6. Repeat 10-50 times

Total Interactions: 50+ clicks for 10 FAQs

Time Required: 45-60 minutes

User Experience: Tedious, high abandonment

✅ NEW WAY: Intelligent Extraction

Scenario: Building FAQ list

  1. Drag/drop existing FAQ doc
  2. AI parses all Q&As
  3. Review parsed pairs
  4. Click ✓ on correct ones
  5. Edit only what needs fixing
  6. Click "Confirm All"

Total Interactions: 5-10 clicks for 10 FAQs

Time Required: 5-10 minutes

User Experience: Fast, feels magical

5. Technical Implementation: How AI Parsing Works

Step 1: Content Ingestion

  • Accept multiple formats (PDF, DOCX, TXT, paste, URL)
  • Extract text with layout preservation
  • Handle tables, lists, formatting
  • OCR for scanned documents
  • Speech-to-text for audio

Step 2: Pattern Detection

  • Identify Q&A patterns (question markers)
  • Detect list structures (bullets, numbers)
  • Find section headers and boundaries
  • Recognize entity types (dates, names, metrics)
  • Map to expected schema

Step 3: Entity Extraction

  • Use frameworks (OCDA, 4Ds) as extraction lenses
  • BizzyBot perspectives for context
  • Component-specific patterns
  • Journey-level requirements
  • Confidence scoring per extraction

Step 4: Validation UI

  • High confidence (90%+): Green checkmark default
  • Medium confidence (70-89%): Yellow, user reviews
  • Low confidence (<70%): Red, manual entry required
  • Show original source context
  • One-click accept for high confidence

8. Configurable Validation Rules Engine

The Power of Configuration: Every Quest, Component, and Spark can have custom validation rules defined that determine what "good enough" looks like and what questions to ask next.

Validation Rule Types

  • Completeness: All required fields filled?
  • Quality: Meets minimum standard?
  • Consistency: Matches other answers?
  • Specificity: Detailed enough?
  • Evidence: Backed by document/data?
  • Actionability: Can be implemented?

Rule Configuration

  • Minimum field count (e.g., "3 referral sources")
  • Minimum text length (e.g., "50 words")
  • Required evidence type (document, metric, example)
  • Cross-validation (checks against other Components)
  • Framework application (must pass OCDA lens)
  • BizzyBot validation (DataBits checks numbers)

Adaptive Questioning

  • If validation fails → ask clarifying question
  • If answer is vague → prompt for specifics
  • If incomplete → show exactly what's missing
  • If inconsistent → highlight conflict
  • If low quality → offer AI improvement
  • If uncertain → lower confidence, flag for review

Graduated Acceptance

  • Green (90%+): Auto-accept available
  • Yellow (70-89%): Requires review
  • Orange (50-69%): Needs edits
  • Red (<50%): Manual entry required
  • Users can override with "Accept Anyway"
  • Elizabeth can set stricter thresholds per Quest

11. Critical Developer Notes

The "Magic Wand" User Experience

  1. Always offer the extraction path first: Don't hide it as "advanced option"
  2. Show progress during AI processing: "Analyzing... found 12 Q&As... extracting details... checking quality..."
  3. Make "Accept All" prominent: For high-confidence items, one-click acceptance should be obvious
  4. Show original source context: When user reviews extracted data, show where it came from in original doc
  5. Enable inline editing: Don't force them to a separate edit screen - edit right in validation view
  6. Auto-save everything: No "Save" button needed - every change persists immediately
  7. Provide "Skip for Now": Always allow partial completion - come back later for gaps
  8. Use optimistic UI: Assume success, show immediate results, handle errors gracefully
